Screen by screen

Attention first, then detail. Every screen answers a question the team actually has.

The console is a single-page application over the same API the MCP endpoint uses. Two contexts: a workspace per project with Overview, Plan, Work, History, Analytics and Settings, and an admin context with the command center, projects, providers, access and usage. Screens below are the live console with other projects' names blurred.

Design system

Encoded state, not decorated state.

The console is scanned and operated, not read. Status is a badge, a failure class is a chip, the channel a job came through is a colour, a stage is an emoji that recurs identically in Slack. Dark by default, light on demand, both from one token set.

Live where it matters

Ten server-sent event streams: jobs, a job's detail and logs, workers, the supervisor feed, chat, job chat, ideation, architect and intake. A running job's timer ticks in the worker card; a terminal job closes its own stream.

Gated, not disabled

Actions the caller cannot perform are not rendered at all, from a single permission helper fed by the role table. Stop on a running application sits behind a confirmation naming it. Deleting a project requires typing its name.

Keyboard and mobile

A command palette on ⌘K switches projects, files jobs and jumps to admin screens. A collapsible icon rail on desktop becomes a five-slot bar on a phone with a More sheet for the rest. Empty states, errors and loading share one component so every screen fails the same way.
